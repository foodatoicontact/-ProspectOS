# Discovery SQL contract (incremental V0)

Use organization_id (not tenant_id). Files db/migrations/*_discovery.sql + tests/discovery-db.mjs, optional SQL test file. No change db/schema.sql or core.ts.

## Tables
- discovery_runs: id uuid, organization_id, project_id, query, location, categories jsonb, provider text enum fixture/brave, filters_json jsonb, status running/completed/failed, started_at, completed_at, result_count int, error_message text, metrics jsonb. composite project FK, unique(id,organization_id), plus unique(id,project_id,organization_id).
- discovery_results: id, organization_id, project_id, discovery_run_id, company_name, website nullable, phone/address/city nullable, source_url/title, provider, external_id nullable, raw_payload jsonb, normalized_payload jsonb, dedupe_key, dedupe_status unique/duplicate_candidate/merge_review_required, duplicate_of uuid nullable (PROSPECT id), status pending/accepted/ignored, prospect_id nullable, reason text, created_at. Composite run/project/tenant FK and prospect references. Results directly insert/update via member JWT allowed with tenant invariants.
- prospect_observations: id, organization_id, prospect_id, criterion nullable, observation_type, claim, value boolean nullable, status OBSERVED/UNKNOWN/INFERRED/CONTRADICTED, source_url, source_title, source_excerpt, source_type, confidence float, collected_at, expires_at, content_hash, evidence_id nullable, review_status NOT_VERIFIED/VERIFIED/CONTRADICTED default NOT_VERIFIED, created_at. Composite FK prospect; add unique(id,prospect_id,organization_id) to evidence and triple evidence FK to prevent wrong prospect. Unique observation identity prospect_id/source_url/observation_type/content_hash to keep repeat analysis idempotent. Only SELECT grants: all writes via checked RPC.
- add nullable discovery_dedupe_key column to prospects and partial unique(project_id,discovery_dedupe_key). Address/phone remain result metadata, phone channel unverified on acceptance.

## RPC exact names and args
1. start_discovery(p_project_id uuid,p_query text,p_location text,p_categories jsonb,p_provider text,p_max_results int,p_filters jsonb) RETURNS jsonb run row. Auth member check; validated sizes, provider and count; atomic quota then run insert. Store max_results in filters_json for service. Result max configured DB cap.
2. consume_analysis_quota(p_prospect_id uuid) RETURNS void. Auth checks and quota.
3. accept_discovery_result(p_result_id uuid,p_force_separate boolean default false) RETURNS jsonb prospect row. Atomic lock result. Ignored -> refuse. Accepted -> return existing. duplicate_candidate + duplicate_of -> return existing ONLY same project. merge_review_required -> reject unless force_separate; if force separate suffix dedupe key result.id, never merge. Unique normal key ensures concurrency safe. Create prospect À analyser, website from candidate.website (not source URL guessed official), city from normalized metadata, public phone channel NOT verified. Set result accepted/prospect_id. Existing new prospect event trigger retained.
4. save_discovery_observations(p_prospect_id uuid,p_observations jsonb) RETURNS jsonb array of saved observation rows. Atomic auth check, max 40; serialize per prospect to avoid orphan proposals. Parse/validate observation fields to match src/discovery/types.ts ObservationSchema. For non-UNKNOWN, criterion in project's active icp criteria (or default food/region/phone_orders/social_orders/platforms/weak_collect/audience/internal_delivery if no ICP), nonempty excerpt and boolean value: insert evidence NOT_VERIFIED or INFERRED_UNCONFIRMED (when INFERRED) using existing model, never VERIFIED, null verified_by. UNKNOWN => no evidence. Insert obs; repeated identical identity preserves existing reviewed row/evidence. Return all requested stored rows.
5. review_discovery_observation(p_observation_id uuid,p_decision text) RETURNS jsonb observation. decisions confirm/contradict/unverify. Auth membership; lock row; cannot confirm UNKNOWN/missing excerpt/value/evidence. Update SAME linked evidence: VERIFIED / CONTRADICTED / NOT_VERIFIED; existing trigger sets actor. update review_status correspondingly. Insert audit event kind observation.confirm etc via same auth member check. This revokes prior verified points when contradicted without changing core score.

## Quotas
Private admin-only settings table singleton: runs_per_hour default 10,max_results default20,analyses_per_hour default20. private usage table with organization/action/time, no public permissions. Private helper uses advisory xact lock tenant+action, counts rolling hour, throws quota_exceeded before insert. All supplied tenant values derived from owned project/prospect. No client-set limit argument. Settings alterable by admin SQL; document no commercial promise. Membership check inside every privileged fn, search_path '', revoke PUBLIC/anon execute, public RPC invoker wrapper delegates private checked function if needed. V0 schema functions available. No service_role client.
